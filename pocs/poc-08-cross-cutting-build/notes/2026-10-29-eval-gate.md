# PoC-8 offline eval gate: normal logic passes, drop-facts fails, 2026-10-29

## Why

Exit criterion 5: "A regression in business logic fails CI through the offline eval." It also backs the "Offline evals" scope item and the first half of the planning doc's demo.

## Setup

- Commit `95c8924`, dirty: one untracked file, `tests/test_poc08_c5_regression.py`, written at the same time by another agent. It is not part of the commands below.
- Machine: macOS 27.0.1, Apple M1 Pro. uv 0.10.10, Python 3.12.13. DeepEval 4.3.2, which `bakeoff` starts in its own `uv run --with` environment.
- No Docker, no kind. A `bakeoff` stack per target: the chassis and the fake model server on localhost TCP. The fake model server plays the engine's model and the judge. No key, no hosted model.
- The golden set: 50 cases (`bakeoff.golden.load_gate_cases`), the 20 PoC-7 cases in `cases.yaml` plus 30 in `cases-gate.yaml`. Ten are labelled `fail` (wrong answers on purpose).
- The baseline: `evals/gate/baseline.json` (`eval-baseline.v0`). 16 targets, one agent (`simplifier`), each at a pass rate of 0.780. 39 `must_pass` and 10 `must_fail` cases. `kagent-adk` is listed under `skipped` (it runs only on kind).
- The target shown: `echo-python` in the `sidecar` lane. CI runs every target, one job per engine (`.github/workflows/poc08-evals.yml`).
- The rule (`bakeoff.evalgate`): a target fails when its pass rate drops below the baseline, a `must_pass` case fails, or a `must_fail` case passes. suggested: no tolerance on the rate, since the model is scripted.

Trimmed: the uv `UV_NATIVE_TLS` warning lines. `bakeoff.evalgate` exits 1 here. The `evals-regression` target turns exactly that exit 1 into its own exit 0. Any other code, including 0, fails the target. CI runs the same target in the `regression` job.

`drop-facts` (`bakeoff.golden.logic`) removes the first expected fact from every scripted answer before the script is generated. No engine, workload, or chassis code changes, so the drop is in the business logic only.

## Reading

The gate passes the normal logic at exactly the baseline (39/50) and fails the drop-facts logic (0/50, all 39 must-pass cases), with exit 1. Criterion 5 passes offline on this target. It stays open for CI until the first GitHub run of `poc08-evals.yml`. The scripted judge shows the mechanics, not judge quality: a real judge's agreement with the labels waits on the Mac run (PoC-7, ADR-010).

## Controls

The failure is not a broken stack: the same command, target, and stack pass on the normal logic (command 1). A `must_fail` case that starts to pass also fails the gate: `packages/bakeoff/tests/test_bakeoff_evalgate.py::test_bakeoff_evalgate_fails_when_a_known_bad_answer_starts_to_pass`. The offline scorer gives the same verdicts on every baseline target: `::test_bakeoff_evalgate_passes_the_normal_logic_on_every_baseline_target`, `::test_bakeoff_evalgate_fails_the_drop_facts_logic_on_every_baseline_target`. The g08 judge miss is pinned by `packages/bakeoff/tests/test_bakeoff_gate_golden.py::test_bakeoff_gate_golden_judge_agrees_with_labels_but_g08_and_fails_dropped_answers`.
