## Why

Exit criteria 2 ("Every supported engine passes the red-team set in CI") and 7 ("Every pipeline stage runs in every lane, and the red-team set passes in each"). It also backs the scope item "The red-team set from PoC-7 runs in CI".

"Passes" here means: each target stops at least what the committed baseline `evals/redteam/baseline.json` records, and no case it stopped gets through. It does not mean 18 of 18. The four misses have owners (below).

- Commit `95c8924`, dirty: untracked test files written at the same time by another agent (`tests/test_poc08_c1_ci.py`, `tests/test_poc08_c5_regression.py`). They are not part of the commands below.

- CI runs the same command per engine in `.github/workflows/poc08-evals.yml`, job `redteam`.

## Reading

Every engine and lane that runs offline stops 14 of 18 on the `litellm` stack and 13 of 18 on `keyword`, equal to the baseline. Every miss has an owner. Criteria 2 and 7 pass offline. They wait on the first GitHub run of `poc08-evals.yml` for the "in CI" part, and on the Mac for Prompt Guard 2 numbers.

The port race is a known risk of starting many stacks in a row on one host. It did not happen in the rerun. If it shows up in CI, the runner should retry a target that did not start, not count it as a pass.

## Controls

A stopped case is only evidence if the target was reachable. Each target ran 18 cases and missed four or five, so its chassis, engine, and model answered. For the misses the unguarded path reached the model. The rerun shows that `echo-pydanticai/remote` starts and runs.
