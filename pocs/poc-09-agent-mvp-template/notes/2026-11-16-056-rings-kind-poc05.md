## Reading

Both boxes pass on a fresh stack (the 14:20 UTC run).

- **The pin through a rollout.** `ring-pin` ran `poc09` through all five steps, on the same pod
  (one uid) with one image id. Over the same steps its ring's other release, `ring-ten`, moved
  from `poc09` to `poc10` onto a new image id. The pin is one value in the service's own values.
- **The rollback is one change.** From `promote-all` to `rollback` one overlay value changed
  (`canary.yaml`'s `chassisTag`, set to `poc09`). Only the canary's pod rolled, and it went back
  to the image name and id it ran before the release. The other three pods kept their uid and
  image.
- **`/manifest` on every service.** After each step, every release's `/manifest` returned 200,
  and its `versions.chassis` equalled the tag of its pod's chassis image. Across all 20 reads,
  each reported version maps to one running image id, and the two ids differ. So the version
  names the image the node runs, not only the chart's env.
- No workload image moved in any step: the same name and image id as before the release.

## Controls

- The pin: its twin in the same ring moved in the same run, so the ring did move under it.
- The rollback: the step before it shows the canary on `poc10` with the other id. The other
  three releases did not roll, so the change reached only the canary.
- `/manifest`: two tags are in play with two image ids. A chassis that always reported one value
  would fail the per-step equality in four of the five steps.

## Not covered (the boxes this run leaves open)

- "A new chassis tag reaches the canary, then 10%, then all services": the box asks for Argo CD
  and its `argoproj.io/Application` health check. There is no Argo CD on `poc05`, and installing
  it adds third-party images (a `platform-security` question). The helm walk above shows the
  same tags per ring, but it is not the sync the box names.
- "A canary with a raised error rate stops the rollout": this needs Prometheus with the `ring`
  relabel rule and `deploy/prometheus/rules/rings.yaml`. There is no Prometheus on `poc05`.
- "The contract suite passes against a pinned workload image built on the previous event schema
  version": there is no previous event schema version yet. The chassis has `events.v0` only
  (`SUPPORTED_SCHEMA_VERSIONS = ("0",)`).
- "The urgent-fix path is ... tried once on the local cluster": its step 2 is a fast-ring release
  "in one sync", which the sync waves order. That needs Argo CD.
- The signature box: parked on the ADR-005 decision. Not attempted.
- Scope of the `/manifest` box: every service the chart delivers. PoC-5's hand-written pods in
  `poc05-agents` (`agent-echo`, `chassis-echo-remote`) do not come from `agent-lib`. They set no
  `CHASSIS_IMAGE_TAG`, so their `/manifest` reports the package version. They were not read.
