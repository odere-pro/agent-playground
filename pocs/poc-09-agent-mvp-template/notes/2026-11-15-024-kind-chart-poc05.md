## Reading

All four boxes pass on a fresh stack.

- **Tag rollout.** A bump in the library chart alone (`poc09` to `poc10`, in a copy of the charts,
  values unchanged) gave each release a new pod. Its chassis runs the new image id; its workload
  runs the same image name and image id as before, so no service image was built.
- **Workload port.** The Service and its EndpointSlice carry port 8080 only. From a pod with no
  egress policy, the chassis port connects and the workload port 9000 times out (dropped by the
  policy, not refused). Inside the pod the workload answers on `127.0.0.1:9000`.
- **Secrets.** From inside the workload container: no `CHART_DRILL_TOKEN` env name, no
  `/etc/chart-drill`, no such line in `/proc/self/mountinfo`, no other process visible (no shared
  process namespace), no service account token. Names and paths only; no value was read.
- **Liveness restart.** SIGSTOP on the workload process (from the node, through `crictl`): its
  exec probe timed out, the kubelet killed it with the probe's own grace (10 s from the kill event
  to exit 137, not the pod's 50 s), started it again in the same pod, and the pod was Ready again
  43 s after the stop. The chassis did not restart.

## Controls

- Workload port: the chassis port on the same pod IP connects from the same caller pod, and the
  workload port answers inside the pod. The timeout is the policy drop (`POLICY_DROPPED`).
- Secrets: the same probe in the chassis container finds the env name, the mount, the
  `mountinfo` line, and a process whose environ holds the name.
- Liveness: before the stop, the pod was Ready, and the test reads the restart count first.
- Tag rollout: before the bump, both pods ran `chassis:poc09` with the same image id.
