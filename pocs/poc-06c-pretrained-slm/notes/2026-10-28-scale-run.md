## Server load

llama-server host CPU (ps, every 2 s, 100 = one core): mean 70, max 98 over 470 samples

How to read the limit: compare the per-container CPU in the results (chassis and workload, capped at 1 CPU each) with the llama-server CPU above (100 = one core) and its slot count (-np 4). If throughput stops growing while the chassis and workload sit below their caps, the model server is the limit.

## Reading

Exit criterion 4. Run: `poc06-slm.yml` run 40724222330 on a 4-CPU GitHub runner, CPU only, one llama-server with 4 slots (`-np 4`).

- **Throughput stops growing at 2 pairs.** OK RPS for echo-python is 1.84, 2.34, and 2.03 at 1, 2, and 4 pairs; for echo-openai-agents 2.16, 2.44, and 1.94. It rises a little from 1 to 2 pairs and falls back at 4.
- **The model server is the limit, not the agent pods.** Each chassis used 0.19 to 0.25 vCPU and each workload 0.09 to 0.17 vCPU, far under their 1-vCPU caps (the `containers` numbers in the results JSON). With 16 users and 4 slots, calls queue at llama-server: p50 is 6 to 8 s per call against 1.9 s for a lone simplifier call in the slm run. More pairs add more queued callers, not more model capacity, and at 4 pairs the extra containers compete with llama-server for the same 4 CPUs.
- **The 13 failures at 1 pair.** echo-python 1 pair failed 13 of 124 calls with "envelope status 'error'", with p95 at 30,000 ms: the run's 30 s budget ran out while calls waited for a slot. The other five scenarios had no failure.
- **What it means for the design.** Agent pods scale apart from the model server, as the plan says, and add almost no cost. The model server's capacity (slots and the hardware behind them) sets the throughput. Here that is CPU decoding on a shared 4-core runner, so the absolute numbers say little about a Mac with Metal or a GPU server. The finding to carry forward is the shape: past 2 pairs per llama-server, add model capacity, not pairs.
- **Server load.** The llama-server CPU line above came from `ps -o %cpu`, which on Linux averages over the process's life (it also ran through the image build), so it understates the load. The script now samples per 2 s interval from `/proc` on Linux.
