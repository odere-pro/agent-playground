## Request features

Exit criterion 3: per engine, the request features the SLM route rejects or ignores.

The path is engine, then the chassis model proxy, then LiteLLM `local-small`, then llama-server. The proxy reads `model`, `messages`, `temperature`, `max_tokens`, `tools`, and `stream`, and ignores every other key (`packages/chassis/src/chassis/server/model_proxy.py:214-225`). So LiteLLM and llama-server see only what the chassis builds:

- `temperature` is 0.0 when the engine sends none (`model_proxy.py:222`, suggested). None of the five engines sends one, so the SLM decodes greedily.
- `max_tokens` is set from the run's budget (`model_proxy.py:620`).
- The LiteLLM adapter adds `metadata.tags` (`packages/chassis/src/chassis/adapters/litellm/client.py:250`) and, on a stream, `stream_options.include_usage` (`client.py:299`).
- LiteLLM serves `local-small` as `openai/local-small` with `drop_params: true` (`deploy/compose/poc06/litellm.config.yaml:19,30`). Thinking is off by a server flag, not a request key.

| Engine | Sends beyond the six keys | Ignored on `local-small` | Effect in this run |
| ------ | ------------------------- | ------------------------ | ------------------ |
| Plain Python (`echo-python`) | `stream_options` | `stream_options` (the adapter re-adds usage) | none: 15 of 15 runs per lane passed |
| PydanticAI (`echo-pydanticai`) | `stream_options`, `tool_choice` (`auto`) | both | none: `auto` is llama-server's default; lookup 5 of 5 with 5 of 5 tool calls in both lanes |
| LangGraph (`echo-langgraph`) | `stream_options` | `stream_options` | none |
| OpenAI Agents SDK (`echo-openai-agents`) | nothing by default | nothing | none. A `tool_choice` or `parallel_tool_calls` set later would be dropped silently |
| TypeScript (`echo-typescript`) | `stream_options` | `stream_options` | none |

What this run confirms, and what it does not show:

- **No request was rejected.** Every one of the 135 runs passed, so no call ended in a 4xx from LiteLLM or llama-server.
- **Tools work end to end.** Every lookup made its two tool calls with valid arguments (`tool_call_pass_rate` 1.0 in every cell), so llama-server's Jinja tool template turns `tools` into `tool_calls` for all five engines.
- **Usage comes back.** Input and output tokens are non-zero in every cell, so the usage the adapter asks for reaches the chassis.
- **Greedy decoding did no harm here.** No run looped or was cut: every answer passed its check. Qwen's model card advises against greedy decoding for Qwen3; with 15 runs per cell that risk did not show.
- **Not observed:** whether LiteLLM's `drop_params` dropped anything, and what it does with `metadata`. The job keeps no LiteLLM log. Neither changes a result above.
