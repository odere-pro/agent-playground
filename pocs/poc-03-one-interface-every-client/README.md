# PoC-3: One interface for every client: OpenAI, Anthropic, and MCP on every engine

Status: done (2026-10-01)
Planning doc: [003-PoC-3-one-interface-every-client.md](../../docs/planning/poc/003-PoC-3-one-interface-every-client.md)
Time box: 1 week

## Question

Can any client call any engine the same way, through native, OpenAI, Anthropic, and MCP interfaces?

## Scope

- [x] `POST /v1/chat/completions` (OpenAI-compatible) in the chassis, streaming and complete. This is the OpenAI interface on the public port, not the model proxy on the proxy port. · evidence: `packages/chassis/src/chassis/adapters/openai_compat/inbound.py`, `server/interfaces/openai.py`; `tests/test_exit_criteria.py::test_exit_3_the_sdks_work_with_only_a_base_url_change[openai]`; `packages/chassis/tests/test_inbound_contract.py` (the OpenAI binding); the `openai` cells of `tests/test_interface_contract.py`, stream and complete
- [x] `POST /v1/messages` (Anthropic-compatible) as an inbound adapter in the chassis, using the official `anthropic` SDK types. · evidence: `packages/chassis/src/chassis/adapters/anthropic_compat/` on `anthropic` 1.11 types; `tests/test_exit_criteria.py::test_exit_3_the_sdks_work_with_only_a_base_url_change[anthropic]`; `packages/chassis/tests/test_inbound_contract.py` (the Anthropic binding); the `anthropic` cells of `tests/test_interface_contract.py`
- [x] An inbound contract suite: the same logical request through every adapter gives the same canonical request, and maps back correctly. · evidence: `packages/contract-suites/src/chassis_contracts/inbound.py` (`InboundAdapterContract`), bound for native, OpenAI, and Anthropic in `packages/chassis/tests/test_inbound_contract.py`: `83 passed, 4 skipped in 2.23s`. The 4 skips are cases a format does not have: native has no `model` field (1), returns `end.output` as is (1), and answers a run error as a 200 envelope (2).
- [x] The OpenAPI 3.1 spec generated by FastAPI. · evidence: `tests/test_openapi_props.py::test_the_spec_is_openapi_3_1_with_every_operation_named_and_labeled`, `::test_schemathesis_sees_every_operation_in_the_spec`
- [x] MCP tools generated from the OpenAPI spec with FastMCP 4 (`from_fastapi`, curated route maps), mounted in the app, with LiteLLM's MCP gateway in front. · evidence for the first half: `tests/test_exit_criteria.py::test_exit_4_an_mcp_client_lists_the_agents_tool_and_runs_it`, `::test_exit_5_mcp_tools_and_rest_come_from_one_openapi_spec`; the tool is built by `FastMCP.from_openapi` over the `/v1/run` operation's spec with route maps, mounted at `/v1/mcp` on the public port (`adapters/mcp/agent.py`; contract v2, "MCP", says why not `from_fastapi`). Evidence for the gateway half: `deploy/compose/litellm/config.yaml` (`mcp_servers.chassis_agent` at `http://chassis:8080/v1/mcp` over the Compose network, no key, no new port) and the demo record [demo/2026-10-01-demo-interfaces.md](demo/2026-10-01-demo-interfaces.md): on each of the four engines, `fastmcp.Client('http://127.0.0.1:4000/mcp/')` listed `chassis_agent-echo` and called it, and the router logged `route=MCP: chassis_agent-echo`. Demo only (`network`), fake variant, with `allow_all_keys: true` because that LiteLLM has no keys; with auth on, the grant is per key or team (026 CH-4). Offline checks: `tests/test_compose_interfaces.py`.
- [x] `GET /manifest`: a first version, built from the config and the OpenAPI spec. · evidence: `packages/chassis/src/chassis/core/manifest.py`, `server/manifest.py`, `schemas/manifest.v0.json`; `InterfaceContract::test_manifest_matches_config_and_openapi` in `tests/test_interface_contract.py`
- [x] An interface contract suite that covers both lanes: every interface × every engine × streaming and complete × both transports (over A2A on localhost in the `sidecar` lane, and over A2A in memory in `inprocess`). · evidence: `packages/contract-suites/src/chassis_contracts/interface.py` (`InterfaceContract`), bound in `tests/test_interface_contract.py`: `138 passed, 33 skipped in 15.31s`. Of the 64 cells, 49 run and 15 skip with a reason: MCP × stream (8 cells; "MCP answers once: FastMCP's OpenAPI tool buffers the HTTP answer") and `echo-typescript` × `inprocess` (8 cells; "inprocess imports a Python handle by path; echo-typescript has none"), one cell in both. The 33 skipped items are those cells' test cases. `sidecar` runs on Unix sockets in the gate.
- [x] Record-and-replay fixtures (vcrpy or pytest-recording) for model calls, so the contract tests run without a live model. · evidence: `packages/contract-suites/src/chassis_contracts/recording.py` (`CassetteTransport`, on vcrpy 8.3.0); `packages/contract-suites/tests/test_recording.py` and `packages/chassis/tests/test_recorded_model.py` (`::test_replay_never_reaches_a_model`, `::test_cassettes_hold_no_key`): `20 passed in 0.32s`; one cassette per engine in `tests/cassettes/interfaces/`, replayed with `--record-mode=none`; `make record-cassettes` re-records offline.
- [x] Schemathesis property tests generated from the OpenAPI spec. · evidence: `tests/test_openapi_props.py::test_every_operation_meets_its_spec` and the three findings (`::test_finding_run_refuses_a_value_of_the_wrong_json_type`, `::test_finding_an_undecodable_body_gets_the_formats_error_shape`, `::test_finding_a_streamed_answer_fits_the_declared_event_stream_schema`), all passing, none `xfail`: `21 passed in 15.71s`

## Exit criteria

Each one has a scenario test in `tests/` or a recorded reason it cannot have one yet.

- [x] The interface contract suite and the Schemathesis tests run offline in CI on every commit. · evidence: `tests/test_exit_criteria.py::test_exit_1_the_suites_run_offline_in_ci_on_every_commit[interface-contract]`, `[schemathesis]`; both run in `make check` (below)
- [x] The contract suite passes for all engines and all interfaces, over both transports. · evidence: `tests/test_exit_criteria.py::test_exit_2_the_contract_suite_covers_all_engines_interfaces_and_both_transports`; `tests/test_interface_contract.py` (49 cells run, 15 skip with a reason, above). Caveat: the TypeScript echo runs in `sidecar` only, and MCP is complete only.
- [x] The OpenAI and Anthropic SDKs work with only a base URL change. · evidence: `tests/test_exit_criteria.py::test_exit_3_the_sdks_work_with_only_a_base_url_change[openai]`, `[anthropic]`. The test's client transport is a Unix socket (no TCP in the gate); `model` is the agent's name (ADR-003, item 3).
- [x] An MCP client lists the agent's tool and runs it. · evidence: `tests/test_exit_criteria.py::test_exit_4_an_mcp_client_lists_the_agents_tool_and_runs_it`
- [x] The MCP tools and the REST API come from the same OpenAPI spec (no hand-written tool definitions). · evidence: `tests/test_exit_criteria.py::test_exit_5_mcp_tools_and_rest_come_from_one_openapi_spec`; `InterfaceContract::test_mcp_tool_schema_is_the_openapi_request_schema`

## How to run

```bash
make test-poc POC=03         # the offline gate for this iteration
make record-cassettes        # re-record the model cassettes, offline, against the fake model server
```

The TypeScript cells need `npm ci` in `packages/workloads/echo-typescript` once; without `node_modules` they skip.
