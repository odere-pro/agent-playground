# PoC-3 open: design decisions (2026-10-01)

Taken when PoC-3 opened, so the developers and testers build against one design. Values the planning docs do not give are marked `suggested:`. Built on the pipeline seam that has landed in `packages/chassis/src/chassis/server/pipeline.py`: `RunPipeline` at `app.state.pipeline` (`ready`, `to_request(...)`, `open(request) -> Run`, which raises `TraceIdInUse`), `Run` (`events()`, `response()`, `complete()`, `close()`), and `RunStream(run, content, media_type=...)`. Versions checked in `.venv`: fastapi 0.141.1, fastmcp 4.0.10, mcp 2.2.0, openai 3.22.1, anthropic 1.11.0, schemathesis 4.28.0, pytest-recording 0.13.4, vcrpy 8.3.0.

## What the installed packages force

These were checked in the installed source. Several decisions below rest on them.

- **The `openai` and `anthropic` SDKs, and the `fastmcp` client, run on `httpx2`, not `httpx`.** A test that hands an SDK its own client passes an `httpx2.AsyncClient`, for example `httpx2.AsyncHTTPTransport(uds=...)`.
- **The SDK request types work as FastAPI bodies.** `CompletionCreateParams` and `MessageCreateParams` are both unions of TypedDicts. FastAPI 0.141 validates them and puts them in the OpenAPI 3.1 spec. Unknown top-level keys are dropped without a word. `messages` comes in as a lazy `ValidatorIterator`: read it once, and catch `ValidationError` while you read it.
- **Both SDKs retry 408, 409, 429, and every 5xx by default, and both obey the `x-should-retry` response header.**
- **Both SDKs raise on a streamed error.** OpenAI raises on a `data:` frame that has an `error` key. Anthropic raises on `event: error`.
- **`FastMCP.from_fastapi`** calls `app.openapi()` once, when it is built. Each tool calls the app in process through `httpx2.ASGITransport`, with a default timeout of 5 s. It forwards the MCP request's headers, but drops `authorization`, `cookie`, and `mcp-session-id`. Tool names come from the `operationId`, or from `mcp_names`. Body properties become the tool's arguments. A non-2xx answer becomes a tool error.
- **vcrpy 8.3 patches `httpx` and `httpx2` transports globally, `ASGITransport` included.** It also reads every response to its end before it returns it, including the requests it ignores (`vcr/stubs/httpx_stubs.py`). So a global cassette would buffer the `sidecar` lane's SSE and the public SSE.
- **pytest-recording's `--block-network` blocks `AF_UNIX` connects too.**
- **Schemathesis's ASGI client runs the app's lifespan** once per app, on its own thread, for the life of the process. Its `positive_data_acceptance` check fails any 400 on a body that fits the schema.

## 1. Module layout

Decision: the pure format mapping lives under `adapters/`, one package per wire format. The FastAPI routers live under `server/interfaces/`.

```
chassis/core/inbound.py                 Ids, Served, ReplyMeta, Refused, the InboundAdapter Protocol, status_for(code, retryable). No SDK
chassis/core/manifest.py                Manifest v0 model -> schemas/manifest.v0.json (make schemas)
chassis/adapters/openai_compat/
  messages.py                           moved from server/model_proxy.py: UnsupportedMessage, is_empty, refuse_extra,
                                        text_of (was _content), tool_calls_of, to_port_message
  inbound.py                            OpenAIInbound: to_request, complete, stream, error (SDK types)
  types.py                              re-exports CompletionCreateParams, ChatCompletion, ChatCompletionChunk, the error model
chassis/adapters/anthropic_compat/
  inbound.py, types.py                  AnthropicInbound; MessageCreateParams, Message, RawMessageStreamEvent, ErrorResponse
chassis/adapters/mcp/agent.py           build_agent_mcp(app, *, agent_name) -> FastMCP (from_fastapi + route maps)
chassis/server/interfaces/
  __init__.py                           mount_interfaces(app, config): reads spec.interfaces
  ids.py                                ids from body, headers, or minted; remint on conflict (section 6)
  native.py                             RunRequest moves here from app.py; NativeInbound; POST /v1/run
  openai.py, anthropic.py               router factories; no `import openai` / `import anthropic` here
  mcp.py                                /v1/mcp mount and lifespan chaining
  errors.py                             RequestValidationError -> 400 in the format's shape, chosen by the route's interface
chassis/server/manifest.py              GET /manifest
```

Correction (2026-10-01, at close): `build_agent_mcp` uses `FastMCP.from_openapi`, not `from_fastapi`, over `run_operation_spec(app)` in `server/interfaces/mcp.py`: the spec of the `/v1/run` operation alone, built by FastAPI's own `get_openapi`, so start-up never builds the whole spec (about 0.25 s). `server/interfaces/` also holds `hold.py` (the hold rule, the run read in a task of its own) and `serve.py` (one call flow for every interface). The layout above is kept as written.

- **Why the split.** The project rule is that a product SDK is imported only under `adapters/`. The layers contract forbids `adapters` from importing `server`, so the router factories, which need `RunPipeline`, sit in `server`. They reach the SDK types through `adapters.*_compat.types`, the same indirect path `server` already uses for `a2a` and `fastmcp`.
- **Why `*_compat`.** These packages are wire formats, not clients of OpenAI or Anthropic. `adapters/litellm` stays the only outbound model client.
- **Shared OpenAI code.** The OpenAI message mapping moves from `server/model_proxy.py` into `adapters/openai_compat/messages.py`. The model proxy and the OpenAI interface both import it from there. No copy is made, and the model proxy's behavior does not change.
- **Lint (a requirement on the developers).** Add one import-linter contract: "openai and anthropic are imported only under chassis.adapters". Its sources are `chassis.core`, `ports`, `fakes`, `server`, and `profiles`, with `allow_indirect_imports = true`.
- **Each adapter has two pure halves.** `to_request(body, headers, *, ids, served) -> Request` raises `Refused(status, headers, body)`. The back-mapping is `complete(response, meta)`, `stream(events, meta)`, and `error(code, message, retryable, meta)`. Neither half does I/O. The ids are minted by the router and passed in, so the mapping is deterministic.

## 2. The canonical request (a transformer agent: `TaskInput {text, data}`)

| Wire | Canonical |
| ---- | --------- |
| The last message. It must be `role: user`; any other last role is 400, which covers Anthropic assistant prefill | `input.text`. Text parts or text blocks are joined with `"\n"` (the model proxy's rule) |
| OpenAI `system` and `developer` messages, in order. Anthropic `system`, a string or text blocks | `input.data.system`, joined with `"\n"`. suggested: the key. The agent's own prompt (`spec.prompt`) still rules, and the workload may ignore this |
| Earlier `user` and `assistant` text turns | `input.data.history: [{"role": "user"\|"assistant", "text": str}]`. suggested: the key |
| `model` | Must equal `agent.name`, else 404. It is not copied into the request: `agent` and `agent_version` are the served ones |
| OpenAI `max_completion_tokens`, else `max_tokens`. Anthropic `max_tokens` | `budget.max_tokens`. When OpenAI sets both and they differ, 400. Missing (OpenAI only) gives the `Budget` default, 2000 |
| `stream` | `request.stream` |
| No field in either format | `budget.timeout_ms` is the default, 30 000. `context_ref` is None |
| `metadata`, `user`, `safety_identifier`, `metadata.user_id` | Dropped and never logged, because they may be personal data. Caller identity is PoC-8's job |

- `data.system` and `data.history` are set only when they are not empty. A plain one-turn call gives `data == {}`, which is exactly what `/v1/run` sends today.
- **The rule for everything else: refuse what the client would read and not find, and ignore what only tunes the answer.**
  - **Refused with 400:** `n > 1`; `logprobs` or `top_logprobs`; non-empty `tools`; `functions`; a `tool_choice` other than `none` or `auto`; Anthropic `mcp_servers` and `container`; `response_format` or Anthropic `output_config.format` asking for JSON; `audio`, or `modalities` with `audio`; `web_search_options`; any content part that is not text, in any message (`image_url`, `input_audio`, `file`, `image`, `document`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, and the rest); assistant `tool_calls` or `tool` messages in the history.
  - **Accepted and ignored:** `temperature`, `top_p`, `top_k`, `seed`, `stop` and `stop_sequences`, the two penalties, `logit_bias`, `store`, `service_tier`, `reasoning_effort`, `thinking`, `prediction`, `cache_control`, `stream_options` (except as in section 3), and the `anthropic-version`, `anthropic-beta`, `Authorization`, and `x-api-key` headers. Each ignored key is counted as `chassis.inbound_ignored{interface, param}`. suggested: the counter name.
- **"The same logical request"** is the tuple `(text, system, history, max_tokens, stream)`, written natively in each format. Every adapter must map it to the same `Request` once `request_id`, `trace_id`, and `idempotency_key` are masked. The native form of that tuple is `{"input": {"text": T, "data": {"system": S, "history": H}}, "budget": {"max_tokens": M}, "stream": s}`. MCP's form is the native body, `stream` false. The suite's cases always set `M`, because Anthropic requires it.

## 3. Back-mapping

- **Hold rule for OpenAI and Anthropic streams.** Send nothing until the first `delta` or the terminal event arrives. If that event is an `error`, answer with an HTTP error, not SSE. This covers the lone `error` of a run that failed before `handle`, and an error raised before any text. Native `/v1/run` keeps its current frames.
- **Usage.** Run `chassis.core.collector.collect` over the events seen, so every format reports the same totals. For a complete run, use the `Response` from `run.complete()`.
- **Answer text.** It is `output.text` when that is a string. When `end.output` has no `text`, the answer is `json.dumps(output, separators=(",", ":"), sort_keys=True)`.
- **OpenAI complete (`ChatCompletion`).**
  - `id: "chatcmpl-<request_id>"`, `object: "chat.completion"`, `created` set when the run opens, `model: <agent>`.
  - One choice: `{role: assistant, content: <text>}` (`""` when there is no text), with `finish_reason: "stop"`.
  - `usage: {prompt_tokens, completion_tokens, total_tokens}`.
  - Headers: `x-request-id`, `x-trace-id`, and `x-chassis-status` (`ok`, `retry`, or `fallback`). suggested: the three header names.
- **OpenAI stream (`ChatCompletionChunk`).**
  - The first chunk is `delta {role: assistant, content: ""}`, then one chunk per `delta`.
  - The last chunk is `delta {}` with `finish_reason: "stop"`. It carries `usage` unless `stream_options.include_usage` is true. In that case a separate final chunk follows with `choices: []` and `usage`, which is the official shape.
  - Then `data: [DONE]`.
  - `start`, `metrics`, and `tool_call` events send nothing.
- **Anthropic complete (`Message`).**
  - `id: "msg_<request_id>"`, `type: message`, `role: assistant`, `model: <agent>`.
  - `content: [{type: text, text}]`, or `[]` when there is no text.
  - `stop_reason: "end_turn"`, `stop_sequence: null`, `usage {input_tokens, output_tokens}`. The cache fields are null.
  - The same headers as OpenAI.
- **Anthropic stream.**
  - `message_start`: the message with `content: []`, `stop_reason: null`, and `usage {input_tokens: 0, output_tokens: 0}`.
  - `content_block_start` (index 0, `{type: text, text: ""}`) is sent at the first `delta`.
  - Then one `content_block_delta` (`text_delta`) per `delta`, and `content_block_stop`, sent only when a block was opened.
  - `message_delta {delta: {stop_reason: "end_turn", stop_sequence: null}, usage: {input_tokens, output_tokens}}`. The SDK takes `input_tokens` from here.
  - Then `message_stop`. No `ping` events. suggested.
- **Errors before the stream, and in complete mode.**
  - Each answer uses the status from the table below, the body in the format's own shape, and `x-should-retry: true|false` from `retryable`.
  - OpenAI body: `{"error": {"message", "type", "param", "code": <chassis code>, "retryable"}}`. The extra `retryable` key matches the model proxy's error body.
  - Anthropic body: `{"type": "error", "error": {"type", "message": "<code>: <message>"}, "request_id"}`.
  - Text that streamed before an error is not repeated in the error body.
- **Errors mid-stream.**
  - OpenAI: one `data: {"error": {...}}` frame, then `data: [DONE]`. No finish chunk.
  - Anthropic: `event: error` with `{"type": "error", "error": {...}}`, then the stream ends. No `message_stop`.

| Case | HTTP | OpenAI `type` / `code` | Anthropic `error.type` |
| ---- | ---- | ---------------------- | ---------------------- |
| Refused body or failed validation | 400 | `invalid_request_error` / `unsupported_parameter`, `unsupported_message`, or `invalid_body` | `invalid_request_error` |
| `model` is not the agent | 404 | `invalid_request_error` / `model_not_found` | `not_found_error` |
| Pipeline not ready | 503 | `server_error` / `not_ready` | `overloaded_error` |
| `a2a.timeout` | 504 | `server_error` / the code | `timeout_error` |
| `engine_error` | 500 | `server_error` / the code | `api_error` |
| Any other retryable code | 503 | `server_error` / the code | `overloaded_error` |
| Any other non-retryable code | 502 | `server_error` / the code | `api_error` |

suggested: the whole table. A 502 tells the client the workload failed, not the chassis. `x-should-retry: false` stops the SDKs from retrying a non-retryable 5xx.

## 5. The two `/v1/chat/completions` routes

Decision: the public route is called the **OpenAI interface** (a client calls the agent). The proxy route is called the **model proxy** (a workload calls a model).

| | OpenAI interface | Model proxy |
| --- | --- | --- |
| Listener | Public, 8080 | Proxy, 127.0.0.1:8090 |
| Code | `chassis/server/interfaces/openai.py`, `operation_id="chat_completions"`, OpenAPI tag `openai` | `chassis/server/model_proxy.py` (unchanged), not in the public spec |
| `model` means | The agent name | The LiteLLM route |
| Telemetry | `chassis.run` and `chassis.requests` with `interface: openai` | `chassis.model.call`, `chassis.model_calls` |

- **Docs rule.** Never write the bare path. Write "the OpenAI interface (`POST /v1/chat/completions` on the public port)" or "the model proxy (... on the proxy port)". Each module's docstring names the other.
- **MCP gets the same care.** The agent's MCP endpoint is `/v1/mcp` on the public port. suggested: the path. The tool endpoint stays `/mcp` on the proxy port. Unlike the chat path, the MCP path is free to differ, so it does.
- **A `model` that is not the agent** gets 404 `model_not_found`. This tells a client that thinks it is calling GPT-4o that it is not. "Only a base URL change" is read as "no custom client". The demo sets `model` to the agent name and passes any placeholder key.
- **The workload never learns which interface was used** (011 H-2): `ctx` gets no interface field.

## 6. Ids

One rule for all four interfaces, in `server/interfaces/ids.py`:

- **`trace_id`:** the native body field when set; else the trace id of a valid inbound `traceparent` (`parse_traceparent`); else `uuid4().hex`.
- **`request_id`:** the native body field when set; else `uuid4().hex`. Never taken from a header.
- **`idempotency_key`:** the `Idempotency-Key` header (011 H-2, suggested); else the native body field; else minted. It is carried only; PoC-4 acts on it.
- **On `TraceIdInUse`:** native `/v1/run` with a body `trace_id` keeps its 409 (contract v1). For every other source (a header, OpenAI, Anthropic, MCP), re-mint once with a fresh `uuid4().hex`, open again, and count `chassis.trace_id_reminted{interface}` (suggested). So SDK clients never see a 409, which they would also retry.
- **Why this keeps correlation.** The proxies' key is still `trace_id_hex(ctx.trace_id)`, unique per in-flight run because `RunRegistry.open` checks and inserts in one step. When an inbound `traceparent` is free, its trace id is the run's trace id, so the client's trace joins the chassis and the workload. The client reads the id it got from `x-trace-id`.

## 7. MCP inbound

- **Tools.** One tool only: `POST /v1/run`. It is built by `build_agent_mcp(app, agent_name=...)` with `route_maps=[RouteMap(methods=["POST"], pattern=r"^/v1/run$", mcp_type=MCPType.TOOL), RouteMap(mcp_type=MCPType.EXCLUDE)]` and `mcp_names={"run": agent_name}`. The tool's name is the agent's name, slugified. Its input schema is the `RunRequest` body schema exactly; no `mcp_component_fn` edits it (H-13 needs the two to be equal). Its description is the route's `description`, which is built from the config.
- **Complete only.** `httpx_client_kwargs={"headers": {"x-chassis-interface": "mcp"}, "timeout": None}`. suggested: the header. The native route reads this header and then:
  - treats `stream` as false;
  - labels telemetry `interface: mcp`;
  - applies the re-mint rule to a body `trace_id`, so a model-chosen id never causes a 409.

  The header gives no trust; a direct caller that sends it only loses streaming. `timeout=None` replaces httpx2's 5 s default; the run's own `budget.timeout_ms` bounds the call.
- **Mount.** Use `mcp.http_app(path="/v1/mcp", stateless_http=True)` behind a 503-until-ready wrapper added with `app.add_route` (the `tool_endpoint` pattern). Stateless, so PoC-4 replicas share nothing. Its lifespan is chained into the public app's lifespan.
- **Build order.** Build it in `create_app`, after every other route, because `from_fastapi` reads the spec once. `/v1/mcp` is `include_in_schema=False`.

## 10. Record and replay of model calls

- **What is recorded:** `LiteLLMModel`'s httpx calls, `POST {base}/chat/completions`, complete and streamed. The test base URL is `http://model.invalid/v1` and the key is `cassette-key-not-real` (suggested). `.invalid` can never resolve.
- **The cassette sits on the model adapter's transport only, never on the global patch** (see "What the installed packages force").
  - It is `chassis_contracts.recording.CassetteTransport(inner, path, record_mode, vcr_config)`, an `httpx.AsyncBaseTransport` built on vcrpy's `VCR(...).get_merged_config` and `Cassette.load`, `can_play_response_for`, `play_response`, `append`, and `_save`. `_save` is private: pin vcrpy.
  - pytest-recording supplies the `--record-mode` option and the `record_mode` and `vcr_config` fixtures.
  - `@pytest.mark.vcr` is not used in the interface suite.
- **Recording runs offline.** With `--record-mode=rewrite`, `inner` is `httpx.ASGITransport(fake_model_server.create_app(script))`, so no socket is needed. Recording through LiteLLM in Compose is a later `network` job (015 H-8).
- **Replay.** With `--record-mode=none`, `inner` is never called. A miss is raised as an `httpx.TransportError` subclass that names the unmatched body, and the binding asserts that there were no misses at teardown.
- **One cassette per engine,** shared by every interface, mode, and lane: `pocs/poc-03-one-interface-every-client/tests/cassettes/interfaces/<engine>.yaml`. The binding also gets `packages/chassis/tests/cassettes/` for a `ModelPortContract` binding of `LiteLLMModel` over cassettes. Matching on the body means an interface that changed the canonical input fails replay.
- **`vcr_config`:**
  - `match_on: [method, scheme, host, port, path, query, body]`, `allow_playback_repeats: true`, `decode_compressed_response: true`;
  - `before_record_request` and `before_record_response` keep only `content-type`;
  - `filter_headers: [authorization, x-api-key, api-key, cookie, set-cookie, x-litellm-api-key]` as a second guard.
- **No key on disk.** `test_cassettes_hold_no_key` scans every `cassettes/**/*.yaml` for `authorization`, `x-api-key`, `bearer`, `sk-`, and the test key.
- **The gate.** `scripts/check_offline.sh` adds `--record-mode=none` explicitly, so no `addopts` can turn recording on. It does not add `--block-network`, which would break the `sidecar` lane over Unix sockets; `--disable-socket --allow-unix-socket` already blocks TCP.
- **New target.** `make record-cassettes` (suggested) re-records with `--record-mode=rewrite`, offline.

## 11. Schemathesis

- **Where it runs.** `pocs/poc-03-one-interface-every-client/tests/test_openapi_props.py`, with `schemathesis.openapi.from_asgi("/openapi.json", app, config=...)`. The app is a module-level `create_app(fake config, ports=<FakeEngine bundle>)` with all interfaces on. Schemathesis runs its lifespan.
- **Endpoints:** every operation in the spec: `/v1/run`, `/v1/chat/completions`, `/v1/messages`, `/manifest`, `/health`, and `/ready`. `/v1/mcp` and the proxy app are not in the spec.
- **Checks on:** `not_a_server_error`, `status_code_conformance`, `content_type_conformance`, `response_headers_conformance`, `response_schema_conformance`, `negative_data_rejection`, `unsupported_method`, `missing_required_header`.
- **Check off:** `positive_data_acceptance`. Each body route accepts a documented subset of a wider schema: `agent` or `model` must name the served agent, and the SDK schemas list features the adapters refuse with a declared 400. Measured: it fails both SDK routes at once.
- **Deterministic and fast:** `generation: {deterministic: true, max-examples: 25, database: "none"}` (suggested: 25). Measured at about 9 s for the two SDK routes at 25 examples each. No stateful phase.
- **Requirements on the developers, so the spec is honest:**
  - Every route has an explicit `operation_id`: `run`, `chat_completions`, `messages`, `manifest`, `health`, `ready`.
  - `/v1/run`: `response_model=Response`. `responses=` declares 200 `text/event-stream`, 400 `{detail: str}`, 409 `{detail: {code, message}}`, and 503 `{detail: str}` as small models. 422 stays FastAPI's.
  - `/v1/chat/completions`: the body is `CompletionCreateParams`, with `response_model=ChatCompletion`. `responses=` declares 200 `text/event-stream`, plus 400, 404, 500, 502, 503, and 504 with an `OpenAIErrorResponse {error: openai.types.ErrorObject}` (unverified: the `ErrorObject` import path) and the `x-request-id` header on 200.
  - `/v1/messages`: the body is `MessageCreateParams`, with `response_model=Message`. It declares the same statuses with `anthropic.types.ErrorResponse`.
  - `/manifest`: `response_model=Manifest`. `/health`: `{status}`. `/ready`: 200 and 503 `{status}`.
  - A `RequestValidationError` on the two SDK routes becomes 400 in the format's shape. A `ValidationError` raised while `messages` is read becomes 400, never 500.

## Requirements on the pipeline seam

- **`RunPipeline.open(request, *, interface="native")`** (suggested: the keyword). It labels `chassis.requests` and the `chassis.run` span. Today `open` takes no interface.
- **`Run.close()` stays idempotent.** Every streaming interface returns `RunStream(run, frames, media_type="text/event-stream")`, so the trace id is freed even when the body is never read.
- **The hold rule needs a peek.** The routers read `run.events()` up to the first `delta` or the terminal event before they choose between an HTTP error and SSE. `run.events()` must allow that: one iterator, consumed by the router.
