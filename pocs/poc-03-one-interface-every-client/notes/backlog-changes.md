# Backlog changes when PoC-3 closes

What the backlog issues should change once this iteration closes. Apply with skill `planning-sync`; issue bodies are edited by hand, order and dependencies in `docs/planning/tools/backlog.py`. No order, size, or dependency changes: `backlog.py` is not touched.

Evidence: `pocs/poc-03-one-interface-every-client/README.md` (ticked boxes), `docs/contracts/contract-v2.md`, `docs/planning/adr/003-chat-formats-onto-the-canonical-request.md`, `notes/2026-10-01-format-gaps.md`, `notes/2026-10-01-debt.md`.

Applied on 2026-10-01 to the `## What` "Status after PoC-3" bullet of 011 H-2, 051 H-13, 015 H-8, 022 H-6, and 026 CH-4. The other items below are for the owner to apply.

## 011 H-2: inbound adapters

- Delivered: the OpenAI interface (`POST /v1/chat/completions` on the public port) and `POST /v1/messages`, streaming and complete, over one call flow (`server/interfaces/serve.py`) with native `/v1/run`; the official `openai` and `anthropic` SDK types; the `InboundAdapterContract` suite bound for native, OpenAI, and Anthropic. Already in the issue's status bullet.
- Delivered in the fix round: `spec.limits` (suggested: `max_tokens_max: 8000`, `timeout_ms_max: 120000`, `body_bytes_max: 1048576`, `messages_max: 256`), refused as 400 `limit_exceeded` and 413; `internal_error` (500, `x-should-retry: false`); a fixed client-facing error text on OpenAI and Anthropic; strict JSON types on `/v1/run` (422). Add to the status bullet.
- Open, from the debt note: complete-mode calls do not watch for client disconnect (PoC-4); `stop`, `stop_sequences`, the OpenAI message `name`, and unknown Anthropic message keys need a decision in ADR-003; native answers 422 where the chat formats answer 400; the lazy-body and validation-text code is in both chat adapters.

## 051 H-13: OpenAPI and MCP tools

- Delivered: OpenAPI 3.1 with an `operationId` and `x-chassis-interface` on every interface route; `GET /manifest` v0; the agent as one MCP tool at `/v1/mcp`, generated by `FastMCP.from_openapi` from the `/v1/run` operation. Already in the issue's status bullet.
- Delivered in the fix round: the MCP inner hop to `/v1/run` forwards only `traceparent`, `tracestate`, and `Idempotency-Key`; the MCP call passes `spec.limits` and the 413 cap. Add to the status bullet.
- Delivered as demo config: LiteLLM's MCP gateway in front of `/v1/mcp` (`deploy/compose/litellm/config.yaml`, `demo/2026-10-01-demo-interfaces.md`), fake variant, `allow_all_keys: true`. The per-key grant stays with 026 CH-4. Say so in the status bullet.
- Open: a run with `status: error` is not `isError` (PoC-8); two tests read FastMCP's private `tool._client`; the issue still says "built with the MCP Python SDK" while the code uses FastMCP 4 (contract v2, "Where the code differs").

## 015 H-8: testing kit

- Delivered: Schemathesis property tests from the OpenAPI spec (`pocs/poc-03-one-interface-every-client/tests/test_openapi_props.py`); the interface contract suite over four interfaces, four engines, two modes, and both lanes (`chassis_contracts.interface.InterfaceContract`, 49 of 64 cells run); record and replay (`chassis_contracts.recording.CassetteTransport`, `make record-cassettes`, replay with `--record-mode=none`); a key scan of the cassettes. Add a "Status after PoC-3" bullet.
- Open, from the debt note: `CassetteTransport` should refuse to record unless the host ends in `.invalid` or the inner transport is ASGI; query-string filtering; the key scan misses key shapes other than `sk-`; vcrpy is pinned to 8.3.0 because of the private `_save`; one Unix-socket uvicorn runner instead of three; the gate grew from about 35 s to about 100-130 s.

## 022 H-6: security middleware

- Delivered ahead of this issue, as a stopgap: `spec.limits` input size and budget ceilings on every public interface. Rate limits per caller are still open. Add a status bullet.
- Open: both listeners share one event loop (`server/cli.py`), so a slow public request delays the proxies; the body cap trusts `Content-Length`; the PoC-8 auth items in the debt note (the in-process MCP hop must not be trusted by loopback or by `x-chassis-interface`; `/manifest`, `/openapi.json`, `/docs`, `/redoc` are public; `x-chassis-interface: mcp` must never be used for billing or quotas); native and MCP still carry the engine's exception text.

## 026 CH-4: chassis-only credentials and egress

- The trace id now comes from an inbound `traceparent` and is echoed in `x-trace-id`. The per-run credential must not derive from it. Add to the issue.
- The hostile suite must probe `/v1/mcp`, the OpenAI interface (public port), `/v1/messages`, and `/v1/run` from inside a workload.
- LiteLLM's MCP gateway in front of `/v1/mcp` runs in the PoC-3 demo with `allow_all_keys: true` (fake variant, no keys). The per-key or per-team grant, and a security sign-off of that setting, are this issue's.

## 014 H-7: observability

- The hold rule keeps the `chassis.run` span in one context (`server/interfaces/hold.py`), proven with the fake telemetry only. The real OpenTelemetry adapter must re-run `test_interfaces.py::test_held_events_enter_and_leave_the_run_in_one_context` against it. Not applied: one line for the owner.
