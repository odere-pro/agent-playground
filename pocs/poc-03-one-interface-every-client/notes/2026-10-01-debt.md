# PoC-3 debt and open items (2026-10-01)

What PoC-3 carries forward. Each item says where it is written down and who owns it: an iteration, a backlog issue (`NNN ID`), or both. Collected from the code, `docs/contracts/contract-v2.md` ("Where the code differs from the decisions' text"), `notes/2026-10-01-format-gaps.md`, and today's test runs. The PoC-2 debt that PoC-3 paid is listed at the end.

## The interfaces

- **Complete-mode calls do not watch for a client that hangs up.** Nothing under `packages/chassis/src/chassis/server/` reads `is_disconnected`. A complete call (every MCP call included, since MCP is complete only) runs until the run ends or `budget.timeout_ms` expires, and the model calls it makes are still charged. A stream stops when the client leaves (`RunStream` closes the run). Written: contract v2, "MCP" (the run's budget bounds the call). Owner: PoC-4.
- **Some chat fields are accepted and lost without a decision.** `stop` (OpenAI) and `stop_sequences` (Anthropic) are ignored and counted, so a client that relies on them gets text past its stop string. The OpenAI message `name` is dropped, not counted. Unknown keys inside an Anthropic message are dropped by the SDK type, while OpenAI refuses them with 400 `unsupported_message` (`adapters/openai_compat/inbound.py`, `_MESSAGE_KEYS`). Written: the gaps note, rows "Sampling and stop settings", "`name` on a message", "Unknown keys in a message". Owner: a decision in ADR-003 (item 1), with 011 H-2.
- **Native and MCP still send the engine's own exception text.** `RunPipeline` turns an engine exception into `engine_error` with `"<type>: <message>"` (`server/pipeline.py`), and native and MCP return it in `output.error.message`. OpenAI and Anthropic send a fixed text per code (`core/inbound.py`, `PUBLIC_MESSAGES`). Pinned on purpose: `packages/chassis/tests/test_serve_failures.py::test_native_keeps_the_engine_message_contract_v1`. Written: contract v2, "Status table". Owner: PoC-8, with 022 H-6.
- **A run with `status: error` is a normal MCP tool result.** An MCP client sees no `isError`; it must read the envelope. Only a non-2xx from `/v1/run` is an MCP tool error (`test_mcp_interface.py::test_a_run_with_status_error_is_a_tool_result_not_an_mcp_error`). Written: contract v2, "MCP"; the gaps note, "MCP tool errors". Owner: PoC-8, when the MCP path is wrapped for auth (051 H-13).
- **Native and the chat formats use different statuses for the same refusal.** Native answers 422 for a budget below 1 and for a value of the wrong JSON type (FastAPI, strict `RunRequest`); OpenAI and Anthropic answer 400 `invalid_body`. Written: contract v2, "Where the code differs". Owner: 011 H-2. suggested: keep native's 422 until a contract change (`chassis-architect`).
- **The body cap trusts `Content-Length`.** `limits.BodyLimit` refuses at once on a `Content-Length` over `body_bytes_max`, and lets a smaller declared length through without counting the bytes (the server's own framing bounds them). A body with no length is counted. The 413 on `/v1/mcp` is plain `{"detail"}`, so an MCP client raises a transport error instead of a tool error (`test_limits.py::test_an_oversized_mcp_tool_call_is_refused`). Owner: 022 H-6 (input size limits).
- **Content parts per message are not capped.** `messages_max` counts messages, not the parts inside one. One Anthropic message with 33,000 text parts fits under the 1 MiB body cap, passes `messages_max`, and costs 0.31 s to map (second review, 2026-10-01). Owner: 022 H-6. suggested: a `parts_max` in `spec.limits`.
- **Logs and spans carry the engine's raw exception text.** The client no longer sees it on OpenAI and Anthropic, but the log line and the `chassis.run` span (`error.message`) still do. An exception can quote an upstream body that holds a chassis-held key. Predates PoC-3. Owner: `platform-security` to decide on redaction and record it in `deploy/compose/SECURITY.md`; 022 H-6 (PII redaction).
- **The key-leak canary covers two headers only.** `packages/chassis/tests/test_no_key_leak.py::test_a_client_key_never_leaks_from_any_interface` plants a key in `authorization` and `x-api-key`. Other carriers (a query string, `api-key`, a body field) are not probed. Owner: 022 H-6, with 015 H-8.
- **The hold rule's span fix is proven with the fake telemetry only.** The run is read in a task of its own so the `chassis.run` span is entered and left in one context (`server/interfaces/hold.py`; `test_interfaces.py::test_held_events_enter_and_leave_the_run_in_one_context`, on `InMemoryTelemetry`). No real OpenTelemetry adapter exists yet to check it against contextvars-based spans. Owner: 014 H-7.
- **In `inprocess`, streams through every interface arrive in one batch.** Inherited from PoC-2: `httpx.ASGITransport` returns the body after the whole app call. The interfaces sit before the connector, so OpenAI and Anthropic streams batch too in this lane. Written: contract v2, "What did not change"; the gaps note, "Per-delta streaming per lane". Owner: 009 CH-1, only if a test needs mid-run events in this lane.

## Auth (PoC-8)

The interfaces have no caller auth yet. When PoC-8 adds it (022 H-6):

- The MCP tool's inner call to `/v1/run` is an in-process ASGI hop (`adapters/mcp/agent.py`). It must not be trusted by its loopback address or by the `x-chassis-interface` header. The caller's identity must be passed on explicitly.
- FastMCP drops `authorization` on that hop, and `_run_headers` keeps only `traceparent`, `tracestate`, and `Idempotency-Key` (`FORWARDED_HEADERS`). So today no caller token reaches `/v1/run` from MCP.
- `/manifest`, `/openapi.json`, `/docs`, and `/redoc` are public. Decide which stay public.
- `x-chassis-interface: mcp` is spoofable by any direct caller (it only loses streaming today, `test_mcp_interface.py::test_a_direct_caller_sending_the_header_only_loses_streaming`). It must never be used for billing, quotas, or any grant.

Owner: PoC-8, 022 H-6; the MCP half with 051 H-13.

## Egress and credentials (PoC-5)

- **The trace id now comes from the caller.** A valid inbound `traceparent` sets the run's trace id on every interface, and OpenAI and Anthropic echo it in `x-trace-id` (ADR-003, item 4). The proxies still key each outbound call to its run by that trace id. The per-run credential PoC-5 adds must not derive from it. Owner: PoC-5, 026 CH-4.
- **The hostile suite must probe the public interfaces from inside a workload.** A workload shares the chassis's network namespace, so it can reach `/v1/mcp`, the OpenAI interface (`POST /v1/chat/completions` on the public port), `POST /v1/messages`, and `POST /v1/run` on the public port, and start a run of its own agent. Owner: PoC-5, 026 CH-4.

## Record and replay (015 H-8)

- **`CassetteTransport` can record against any host.** suggested: refuse to record unless the host ends in `.invalid` or the inner transport is ASGI, so a cassette is never recorded from a real provider by mistake (`packages/contract-suites/src/chassis_contracts/recording.py`).
- **No query-string filtering.** Headers are filtered to `content-type` only (`test_recording.py::test_nothing_but_content_type_is_stored`), but a key in a query string would be stored. suggested: vcrpy's `filter_query_parameters` for key-like names.
- **The key scan misses key shapes other than `sk-`.** `packages/chassis/tests/test_recorded_model.py::test_cassettes_hold_no_key` looks for auth headers, bearer tokens, the `sk-` shape, and the test key. Other providers' key shapes would pass.
- **vcrpy is pinned to 8.3.0** because `recording.py` calls the private `Cassette._save` (`packages/contract-suites/pyproject.toml`). Check `_save(force=...)` before moving the pin.

Owner: 015 H-8 for all four.

## Tests and code shape

- **Two tests read FastMCP's private `tool._client`** to check the inner client's timeout and header hook (`packages/chassis/tests/test_mcp_interface.py`, lines 300 and 515). A FastMCP upgrade can break them. Owner: 051 H-13.
- **Duplication.** Reading the lazy body and formatting a validation error's text exist in both chat adapters (`adapters/openai_compat/inbound.py`, `adapters/anthropic_compat/inbound.py`; the router copy in `server/interfaces/errors.py`, `validation_message`). The uvicorn-on-a-Unix-socket runner exists twice in `pocs/poc-02-two-engines-one-contract/tests/poc02_harness.py` and once in `packages/contract-suites/src/chassis_contracts/interface.py` (`serve_on_unix_sockets`). Owner: 011 H-2 for the adapters, 015 H-8 for the runners (the test kit should ship one).
- **Both listeners share one event loop.** `chassis serve` runs the public and the proxy uvicorn servers with one `asyncio.gather` (`server/cli.py`). A slow or heavy public request delays the model proxy and the tool endpoint a running workload is waiting on. Owner: 022 H-6, with the rate limits.
- **The gate is slower.** `make check` took about 35 s at the PoC-2 close (`673 passed, 18 skipped, 14 warnings in 34.74s`) and takes about 100-130 s now; today's run is in the README, "Gate runs". Most of it is the interface matrix (one chassis per engine and lane, on Unix sockets) and Schemathesis. Owner: 015 H-8. suggested: split the matrix into its own CI job if the gate passes 3 minutes.

## Demo only

- **LiteLLM's MCP gateway runs with `allow_all_keys: true`.** `deploy/compose/litellm/config.yaml` grants `mcp_servers.chassis_agent` to every caller, because the fake variant's LiteLLM has no keys and a caller with none lists 0 tools (seen 2026-10-01). It widens nothing there, but it is not the setting for a variant with auth on, where the grant is per key or team, and `platform-security` has not signed it off. The gate checks the entry has no key, no auth header, and no new port (`tests/test_compose_interfaces.py`). Owner: PoC-5, 026 CH-4 ("MCP gateway tool grants on that key").
- **The gateway was demoed in the fake variant only**, with `fastmcp.Client`, not Claude Code or Claude Desktop, and not with a real model. Owner: PoC-6a for real models; the desktop client is a demo choice, not a criterion.
