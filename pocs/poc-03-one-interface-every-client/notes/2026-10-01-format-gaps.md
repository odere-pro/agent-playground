# PoC-3: gaps between the formats (2026-10-01)

Exit criterion 6: "Any gaps between the formats are listed (for example tool calls or stop reasons that do not map one to one), with how each is handled".

This note is section 4 of the open note (`2026-10-01-open.md`), corrected against the landed code and extended with what the developers and testers found. The code is the truth: `packages/chassis/src/chassis/core/inbound.py`, `adapters/openai_compat/inbound.py`, `adapters/anthropic_compat/inbound.py`, `adapters/mcp/agent.py`, and `server/interfaces/`. The decisions behind the rows are in [ADR-003](../../../docs/planning/adr/003-chat-formats-onto-the-canonical-request.md) (proposed). The wire contract is in [contract v2](../../../docs/contracts/contract-v2.md).

## The rule

- **Carry** what every format can say the same way: the last user text, the system prompt, earlier text turns, the token budget, and `stream`.
- **Refuse with 400** what the client would read and not find: client tools, more than one answer, logprobs, media, structured output formats, and the like.
- **Ignore** what only tunes the answer, and count it as `chassis.inbound_ignored{interface, param}` (suggested: the name).
- **Drop, uncounted,** what may identify a person: `metadata`, `user`, `safety_identifier`, `user_profile_id`. Caller identity is PoC-8's.

The rows once marked "in progress (decided)" landed in the fix round: strict JSON types on `/v1/run`, the declared event-stream schema, and the route's own error shape for a body that cannot be parsed. Their Schemathesis findings in `test_openapi_props.py` now pass; none is `xfail` any more. The fix round also added `spec.limits`, the 413 body cap, `internal_error`, and the fixed client-facing error text (rows marked "fix round").
