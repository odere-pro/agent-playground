## The lanes and the template server

- **In `inprocess`, the run deadline does not stop `handle`.** The connector's deadline ends the stream with one `a2a.timeout` in every lane. In `inprocess` no event and no task id reach the connector before the batch arrives, so it sends no cancel, and `handle` runs on server-side until it finishes (`packages/chassis/src/chassis/adapters/a2a/inprocess.py`; contract v1, "Timeout and cancel"). Owner: 009 CH-1. It needs a cancel path without a task id, or a streaming ASGI bridge.
- **`EngineConnectorContract.test_cancel_is_clean` proves nothing in `inprocess`.** It reads `start` and closes the stream. In `inprocess` the whole run has finished by then, so there is nothing left to cancel. Owner: 009 CH-1, with the item above.
- **The model call's own timeout is not capped at the run's budget.** `LiteLLMModel` uses 60 s per call (suggested) because `ModelPort.complete` and `.stream` take no per-call timeout (`packages/chassis/src/chassis/adapters/litellm/client.py`). The workload's own client caps its call at `budget.timeout_ms` instead. Owner: 013 CH-2 (needs a `ModelPort` change, so also 012 H-3).
- **The Python template servers cannot interrupt `handle` mid-await.** `cancel` sets a flag and publishes `CANCELED`; `execute` stops at its next step and closes the generator in its own task. A pending await (a model call in flight) runs to its end, and an update whose publish was already in flight can still arrive after `CANCELED`. The TypeScript server aborts `deps.signal` and stops the call. Written in contract v1, "Timeout and cancel". Owner: 009 CH-1 (the template server), carried into 025 H-10.
- **A JSON-RPC error answer surfaces as `engine_error`, not an `a2a.*` code.** a2a-sdk raises it as an `A2AError` that is not an `A2AClientError`, so the connector does not map it and the pipeline turns the exception into `engine_error`. Owner: 009 CH-1. suggested: map it to `a2a.transport` or a new `a2a.rpc_error`, with `chassis-architect`.
- **The `inprocess` lane still batches events.** `httpx.ASGITransport` returns the body after the whole app call, so every event, the first `delta` included, arrives at the end of the run (`notes/2026-10-01-measurements.md`, "Time to first token"). Accepted: `inprocess` is for tests and local runs only (ADR-001 item 4). Owner: 009 CH-1, only if a test needs mid-run events in this lane (a streaming ASGI bridge).
- **`a2a.unsupported_state`'s message still says "not in contract v0"**, in both byte-equal copies of `mapping.py` (`packages/chassis/src/chassis/adapters/a2a/mapping.py` and `packages/workload-a2a/src/workload_a2a/mapping.py`, line 206). A code change, so not made here. Owner: the next change to `mapping.py` under 009 CH-1; change the chassis copy, then copy the file (`packages/workload-a2a/tests/test_workload_a2a_copies.py` checks they match).
- **ADR-002 said one `a2a_server.py` per workload container.** The code has one shared `workload_a2a` package. Amended on 2026-10-01 in `docs/planning/adr/002-template-a2a-server-placement.md`, "Amendment (2026-10-01)". Owner: 025 H-10, which ships it in the template.

## The proxies and budgets

- **There is no per-replica budget for uncorrelated model calls.** A call with no `traceparent`, a bad one, or one that names no in-flight run is served, counted as `chassis.model_calls_uncorrelated`, and logged, with no limit. ADR-001 item 6 and the PoC plan's risk table say it counts against a per-replica budget. Owner: 013 CH-2; refusing such calls is PoC-5 egress work (026 CH-4).
- **The MCP endpoint names the run but does not charge it.** Its `chassis.tool.call` span records the parsed trace id and, for an in-flight run, its `request_id`; it does not charge the run or count uncorrelated tool calls (ADR-001 item 6, "the proxies key every outbound call"). Owner: 054 H-16.
- **The trace id is the proxies' key, and it is not a credential.** `/v1/run` refuses a second in-flight run on one trace id (409 `trace_id_in_use`, suggested), so the key stays unique, but any caller can name any trace id. Owner: PoC-5, which replaces it with a chassis-minted per-run credential (026 CH-4).
- **`ScriptedModel.calls` does not record `max_tokens`.** It keeps the messages of each call only (`packages/chassis/src/chassis/fakes/model.py`), so a test of the capped `max_tokens` cannot read it from the fake. Owner: 012 H-3.
- **No workload uses OpenTelemetry httpx instrumentation.** The plan suggested it; each workload sets `ctx.traceparent` as a plain header instead, which every engine passes today. Spans from inside the workload are not joined to the chassis trace. Owner: 014 H-7.
- **Real token counts need the `local` Compose variant.** The token overhead in the measurements note is a byte-count proxy, and the fake model's scripted usage is the same for every engine by construction. Owner: PoC-6a (the bake-off measures framework overhead on real models), with the counting in 004 G-2.

## Paid in the PoC-2 fix round (2026-10-01)

- **`budget.timeout_ms` was a per-read timeout only.** It is now also a run deadline in every lane (`packages/chassis/src/chassis/adapters/a2a/connector.py`; `LaneContract::test_the_run_deadline_ends_a_stalled_run_in_every_lane`). What remains is the `inprocess` item above.
