# packages/eval-kit

The eval code on the bake-off stack: the PoC-7 eval tool trial, the PoC-8 eval gate, and the PoC-8 red team. Modules and commands are in `README.md`. It moved out of `bakeoff` in R6-14.

- It may import `bakeoff` (`stack`, `registry`, `envs`, `procs`, `config`). `bakeoff` never imports `eval_kit`; import-linter and `packages/bakeoff/tests/test_bakeoff_no_eval.py` enforce it. Never imported by the chassis.
- No agent framework, no product SDK, and no key. The eval tools never enter `uv.lock`. Each run installs them into its temp dir from a committed, hashed lock (R7-18): DeepEval with `uv pip install --require-hashes --no-deps -r evals/deepeval/requirements.txt`, promptfoo with `npm ci` from `evals/promptfoo/package-lock.json` (`evaltrial.tool_install_argv`). Never install one by name (`--with`, `npx`). To bump: edit `requirements.in` or `package.json`, then `uv pip compile evals/deepeval/requirements.in --generate-hashes --universal --python-version 3.12 -o evals/deepeval/requirements.txt` or `npm install --package-lock-only --ignore-scripts` in `evals/promptfoo`; `test_eval_kit_tool_locks.py` checks every entry has a hash. Their telemetry is always off (`evaltrial.TELEMETRY_OFF`). Langfuse credentials come from the environment only and are never printed.
- Every spawned process gets `bakeoff.envs.build_env(...)` and runs through `bakeoff.procs.Cleanup`, as in `packages/bakeoff/CLAUDE.md`.
- The golden set is `golden/cases.yaml` (the PoC-7 20) plus `golden/cases-gate.yaml` (the PoC-8 gate, 50 in all). After an edit run `uv run python -m eval_kit.golden.generate --write`; `test_eval_kit_golden.py` and `test_eval_kit_gate_golden.py` check the generated scripts and promptfoo tests. `evals/deepeval/test_golden.py` reads `golden/cases.yaml`.
- Baselines: `evals/gate/baseline.json` and `evals/redteam/baseline.json`. Rewrite them only from real runs (`--record`), never by hand. A business-logic variant (`--logic drop-facts`) is a generated model script, never engine or chassis code.
- `evalcheck` is the offline reference scorer for tests; CI scores with DeepEval. Make targets: `evals`, `evals-regression`, `redteam`. CI: `.github/workflows/poc07-evals.yml`, `.github/workflows/poc08-evals.yml`.
- `bakeoff` keeps one compatibility module per moved CLI (`evaltrial`, `evalgate`, `evalrun`, `redteam`, `langfuse_datasets`, `golden.generate`), so the commands in dated notes still run. Write new commands as `python -m eval_kit.<module>`.
- Tests start with the package name (`test_eval_kit_*`). A test that spawns a process on a socket is marked `network`.
