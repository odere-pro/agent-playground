## A. The model port (`chassis.ports.model`)

1. **Three port-level codes.** `service_budget_exhausted` (the model service refused for the service's budget; not retryable), `timeout` (the call passed its `timeout_s`, or a transport timeout; retryable), `run_ended` (the run the call belongs to ended first; set by the proxy, never by an adapter; not retryable). Any other upstream status stays `http_<status>`.
2. **`timeout_s` on `complete` and `stream`.** The wall clock of the whole call, in seconds; `None` is the adapter's default (60 s per httpx operation, suggested). Past it the adapter raises `timeout` and ends the upstream call. Evidence: `ModelPortContract.test_a_call_ends_at_its_timeout`, bound for `ScriptedModel` and `LiteLLMModel`; `packages/chassis/tests/test_litellm_failures.py::test_a_call_past_its_deadline_closes_the_upstream_connection` (the fake model server on a real socket counts the close).
3. **No adapter retries.** One port call is one upstream call. The retries and the fallback routes are the model router's (`num_retries` and `fallbacks` per route in every LiteLLM config under `deploy/`). Evidence: `ModelPortContract.test_a_failed_call_goes_upstream_once`; `packages/chassis/tests/test_litellm_route_resilience.py`.
4. **LiteLLM's budget refusal.** A 4xx whose body is `{"error": {"type": "budget_exceeded", ...}}` (LiteLLM's `BudgetExceededError`; 400 or 429 across releases) is `service_budget_exhausted`. Evidence: `test_litellm_failures.py::test_litellms_budget_refusal_is_service_budget_exhausted`.

## B. The model proxy, both routes

5. **The service's budget: 429.** `service_budget_exhausted` answers 429 with the fixed text `the service's model budget is exhausted` and `x-should-retry: false`. On the Anthropic proxy route the type is `rate_limit_error`; on the chat route the body is `{"error": {"message", "type": "model_error", "code": "service_budget_exhausted", "retryable": false}}`, and mid-stream it is one error frame then `[DONE]`. Counted `chassis.model_budget_exhausted{route}`, exported as `chassis_model_budget_exhausted_total`. Evidence: `packages/chassis/tests/test_model_proxy_failures.py`, the four budget tests.
6. **The run's remaining time.** A correlated call's `timeout_s` is what the run has left of `budget.timeout_ms`; an uncorrelated call gets none. Evidence: `test_model_proxy_failures.py::test_a_correlated_call_gets_the_runs_remaining_time`.
7. **A run that ends mid-call: 403 `run_ended`.** The port call is cancelled (the adapter closes the upstream connection) and both routes answer 403 `permission_error`, `the run this call belongs to has ended`, not retryable, `x-should-retry: false`. It is the same class as `run_required`: no run in flight for this call. Evidence: `test_model_proxy_failures.py::test_a_chat_call_whose_run_ends_is_cut_and_answered_403_run_ended`, `::test_an_anthropic_call_whose_run_ends_is_cut_and_answered_403_run_ended`.
8. **`x-should-retry` on every chat-route error.** Every complete-call error on the chat route carries `x-should-retry` from `retryable` (the Anthropic route always did). The OpenAI and Anthropic SDKs read it before their own status rules, so a non-retryable 500 or 429 is not retried by the client. Evidence: `test_model_proxy_failures.py::test_every_chat_error_carries_x_should_retry_from_retryable`.

## C. Operations

9. **The alert.** `ChassisModelBudgetExhausted` in `deploy/prometheus/rules/chassis.yaml` fires on any increase of `chassis_model_budget_exhausted_total` over 15 minutes (`for: 1m`, `severity: critical`; suggested). The PoC-8 Compose stack mounts the file. Evidence: `packages/chassis/tests/test_alert_rules.py`; the fault test `pocs/poc-08-cross-cutting-build/tests/test_poc08_stack_metrics.py::test_a_budget_refusal_raises_the_counter_and_fires_the_alert` (`COMPOSE_STACK=1`).
10. **The fake model server.** An error rule with a `type` answers in LiteLLM's error shape; a rule with `delay_s` holds the answer and counts a client that leaves in `app.state.aborted`.

## D. Backpressure (135 CH-15)

11. **`spec.limits.max_in_flight`** (32, suggested): the most runs in flight on one replica, counted in the run registry (`len(app.state.runs)`). Reloadable with `spec.limits`; read per call. Evidence: `packages/chassis/tests/test_backpressure.py::test_max_in_flight_reloads_with_spec_limits_and_no_restart`.
12. **503 `overloaded`.** At the cap, every public interface refuses the next call before the engine sees it: `Retry-After: 1` (suggested), `retryable: true`; native `{"detail": {"code": "overloaded", "message"}}`, OpenAI `server_error` with `x-should-retry: true`, Anthropic `overloaded_error`. `/ready` stays 200; the drain order (ADR-012) is unchanged. Evidence: `test_backpressure.py::test_a_third_run_past_the_cap_is_503_overloaded_and_never_reaches_the_workload`, `::test_the_chat_interfaces_refuse_in_their_own_shape`, on a real uvicorn server over a Unix socket.
13. **Metrics.** `chassis_requests_refused_total{reason="overloaded"}` and the gauge `chassis_runs_in_flight`, set from the registry at scrape time. Evidence: `test_backpressure.py::test_metrics_show_the_refusal_and_the_runs_in_flight`.
14. **The chart.** `hpa.runsInFlight.enabled` adds a Pods metric on `chassis_runs_in_flight` (`targetAverageValue` 24, suggested) next to CPU; a metrics adapter must serve the gauge. Evidence: `pocs/poc-09-agent-mvp-template/tests/test_poc09_chart.py::test_hpa_scales_on_the_in_flight_gauge_when_asked`.

## E. A JSON-RPC error from the workload (009 CH-1, P-9)

Added 2026-11-13. Decided by the user on 2026-11-13 ([proposals.md P-9](../reviews/2026-11-06-backlog-review/proposals.md#p-9-a-json-rpc-error-from-the-workload), option 1). It replaces the v1 note "A JSON-RPC error answer from a server is not mapped by the connector".

15. **`a2a.rpc_error`.** A JSON-RPC error answer from the workload, with any code, ends the run with one `error {code: "a2a.rpc_error", retryable: false}`, never an exception from `run`, so it is no longer the pipeline's `engine_error`. a2a-sdk 1.2 raises a code in its own map as an `A2AError` subclass, and any other code (`-32000` to `-32099`, or a custom one) as a plain `A2AClientError` whose text starts with `JSON-RPC Error `. The connector reads that prefix in one SDK-pinned helper, `is_jsonrpc_error_answer`; every other `A2AClientError` stays `a2a.transport`. It applies in every lane, from the shared `A2AConnector`. The message is the exception text cut to `ERROR_MESSAGE_MAX` in chassis mode. In the plain mode of `remote` it is the fixed text `the remote failed`, and the remote's words go to the log only. The code is additive: the frozen codes and their `retryable` values do not change (contract v5, C.3). Evidence: `packages/chassis/tests/test_a2a_cancel_rpc.py::test_a_jsonrpc_error_answer_is_an_a2a_code[*]` (`inprocess` and `sidecar`, codes -32603, -32001, -32000, 42), `::test_the_sdk_still_builds_an_unmapped_code_as_a_prefixed_client_error[*]`, `::test_a_mapped_code_is_an_a2a_error_and_other_client_errors_are_not_answers`; `packages/chassis/tests/test_remote_connector_plain.py::test_a_jsonrpc_error_answer_is_rpc_error_in_chassis_mode_too` (`remote`, chassis mode), `::test_the_remote_words_in_a_transport_error_stay_in_the_log[jsonrpc-error-unmapped]`, `[jsonrpc-error-mapped]` (`remote`, plain mode).
16. **The interfaces.** Not retryable, so 502 on the OpenAI and Anthropic interfaces by the existing row of `status_for`, and a 200 envelope with `status: error` on native and MCP. The public text is `the agent refused or failed the request` (`PUBLIC_MESSAGES`; suggested: the text). Evidence: `packages/chassis/tests/test_inbound.py::test_a_jsonrpc_error_from_the_workload_is_502_with_a_fixed_public_message`.

## F. A run's call may name only the run's route (012 H-3)

Added 2026-11-13, by user decision: a call of a run that names any route but the run's own is refused, never redirected. For calls of a run, this section replaces [contract v6](contract-v6.md), G.4, line 376 ("the proxy sends every model call of that run there, whatever `model` the workload names"), in full. The `chassis.model_route_forced{route}` counter is removed. A call with no run in flight keeps R6: it is pinned to `spec.model.route` and counted `chassis.model_route_pinned{route}`.

17. **The run's route only.** A call of a run is admitted only when its `model` is `RunRecord.model_route`: the route of `input.data.task` through `spec.model.routes`, else `spec.model.route`. For the evaluator gate's fallback attempt the gate sets both `RunRecord.model_route` and `ctx.model_route` to `spec.model.fallback_route`, so a workload that sends `ctx.model_route` keeps working. The run's route passes even after a reload drops it from the config: a run keeps the route it opened with. Evidence: `packages/chassis/tests/test_model_route_denied.py::test_a_call_on_the_resolved_route_passes`, `::test_a_run_keeps_its_own_route_after_a_reload_drops_it`, `::test_the_gates_fallback_route_is_the_runs_route_for_its_attempt`; `packages/chassis/tests/test_evaluator_gate.py::test_the_proxy_sends_every_call_of_the_fallback_attempt_to_the_fallback_route`.
18. **403 `model_route_denied` for any other route.** A route the config lists included. The call is refused before any budget is held and before the model is called. The body is the same as an upstream 401 or 403 (contract v5, A.9): `permission_error`, `model_route_denied`, `this model route is not allowed for this service`, not retryable; it names no route and no key. On the chat route a stream gets the 403 as its status, one error frame, then `[DONE]`; on the Anthropic route it is JSON, also for `stream: true`. Counted `chassis.model_route_refused{route}` by the run's route (suggested), and logged once with the asked route cut to 64 characters (suggested). A run record with no route fails closed: every route is refused, counted under `route="unresolved"` (suggested). Evidence: `test_model_route_denied.py::test_another_route_is_403_model_route_denied`, `::test_a_run_with_no_resolved_route_refuses_every_route`; `test_evaluator_gate.py::test_a_fallback_attempt_on_the_first_route_is_refused_not_redirected`.
19. **What it does not cover.** The chassis does not hold the LiteLLM key's route list. A run's own route that the key does not list is refused by the router with the same 403 (contract v5, A.9).
20. **Bounded metric labels.** `chassis.model_calls{route}` counts the route a call is sent to. A call refused under item 18 is counted by the route it named only when `ModelSpec.declared_routes()` lists it, else under `route="other"` (suggested). `chassis.model_stream_timeout{route}` and the Anthropic route's model-error counters label the routed route too. `model` is at most `MODEL_MAX_CHARS` (256, suggested) characters on both routes: over it the OpenAI route answers 422 and the Anthropic route 400 `invalid_body`, before admission and uncounted. So refused calls with new names add no metric series. Evidence: `packages/chassis/tests/test_model_route_hardening.py::test_refused_calls_with_new_long_names_add_no_metric_series`, `::test_uncorrelated_calls_with_new_names_count_the_pinned_route`, `::test_an_over_long_model_is_refused_before_admission`, `::test_an_uncorrelated_stream_timeout_counts_the_pinned_route`.
21. **The route check comes before the budget.** A run with no tokens left that names another route gets 403 `model_route_denied`, not 429 `budget_exhausted`. Evidence: `test_model_route_denied.py::test_a_spent_run_naming_another_route_is_403_not_429`.
22. **Known gap: an uncorrelated call during a run.** In a lane with no `RequireRun` (in-pod, sidecar) a workload can drop `traceparent` while its run is in flight. The call is pinned to `spec.model.route` (R6, unchanged) and charged to the uncorrelated cap, never to the run; a cap of `0` refuses it with 403 `uncorrelated_refused`. Evidence: `test_model_route_hardening.py::test_an_uncorrelated_call_during_a_run_is_pinned_and_capped`, `::test_an_uncorrelated_call_during_a_run_is_refused_under_a_cap_of_0`.
23. **Plain A2A mode has one route.** A plain remote (`spec.engine.protocol: a2a`) never receives `ctx`: the request carries only the input text and data parts, no metadata (`chassis.adapters.a2a.plain.plain_message`). It cannot learn a task route or the gate's fallback route, so `spec.model.routes` and `spec.model.fallback_route` are refused at config load with that protocol. Evidence: `packages/chassis/tests/test_config_plain_a2a.py::test_plain_mode_refuses_task_routes_and_the_fallback_route`, `::test_plain_mode_keeps_its_one_route`.
