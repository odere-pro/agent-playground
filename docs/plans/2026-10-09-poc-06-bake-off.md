## Decisions (user, 2026-10-09)

1. **Remote solution: kagent on the kind cluster.** This is the planning doc's suggested default, since [001 DEC-1](../planning/issues/001-DEC-1-resolve-open-decisions.md) names no first cloud. No cloud runtime (AgentCore, Vertex AI Agent Engine) and no cloud auth adapter in PoC-6.
2. **No local models in 6a and 6b; the SLM gets its own PoC, 6c.** The chassis and the workloads do not care where a model runs. They see one model proxy, and LiteLLM routes the call. So 6a and 6b run every task on one hosted model through LiteLLM (`big-default`), with the provider key in `deploy/compose/.env`, as in PoC-1. Offline runs use the fake model server.
   - Scope change: "run every task on a big model and on an SLM" and exit criterion 5 now say "on a hosted big model" in the planning doc and both READMEs. The SLM half moved to [PoC-6c](../planning/poc/006c-PoC-6c-pretrained-slm.md): a pre-trained Qwen3-1.7B, not fine-tuned, served once by llama.cpp behind LiteLLM's `local-small` route, run by every 6a engine with only `spec.model.route` changed.
   - 6c needs 6a's engines and benchmark kit (P1, P2, A1 to A3). It runs on Compose with a model server, not on kind, so it can run next to 6b. It adds an SLM section to the bake-off ADR.
3. **Sequencing.** PoC-5 ([odere-pro/agent-playground#14](https://github.com/odere-pro/agent-playground/pull/14)) merged on 2026-10-09. Amended the same day by the user: `chassis/poc-unit` (WS1 of [the parallel work plan](2026-10-09-parallel-poc-work.md)) is skipped for this run, and 6a, 6b, and 6c run now, in one worktree off `main`. PoC-6 test files carry the `test_poc06a_`, `test_poc06b_`, and `test_poc06c_` prefixes, so the restructure can still happen later.
6. **Execution (user, 2026-10-09).** A team of agents builds 6a, 6b, and 6c, with the main session as orchestrator and judge. The hosted big model and the SLM run through one command on the user's Mac, `make poc06-mac`, which also brings up kind for the untrusted engines. No provider key enters the cloud container. The run ends with one PR to `main`.
4. **Optional frameworks: none.** Google ADK is skipped.
5. **Languages.** The container is language-agnostic. Python and TypeScript are the common choices, and the shortlist covers both: the Python frameworks plus the TypeScript agent. No new criterion. The TypeScript agent is `echo-typescript` grown into a full agent, with no TypeScript framework.

## Task spec

Every engine runs these three tasks. The strings are suggested, and the fake model scripts them in `packages/fake-model-server/scripts/bakeoff.yaml`.

| Task | Input | Pass when |
| ---- | ----- | --------- |
| Smoke (the super simple check) | `simplify: Hello.` | `end{status: ok}` after at least one `delta` |
| Simplifier | `simplify: The SLM, released in 2026 by Acme, cut costs by 30 percent.` | The output contains `2026`, `Acme`, and `30` |
| Lookup | `lookup: Define SLM and expand RAG.` | `tool_call` `glossary_lookup{term: SLM}`, then `acronym_expand{acronym: RAG}`, with arguments valid against each tool's schema. The answer contains `small language model` and `retrieval-augmented generation` |

`acronym_expand(acronym)` is the second read-only tool. It returns `{acronym, expansion}`, with `expansion: null` for an unknown acronym (suggested data: RAG, SLM, LLM, MCP, A2A, TTFT).

## Execution

The waves run in a worktree of the integration branch. Each task runs in its own worktree and is merged after a check against its acceptance criteria.

- **W0.** Pull `main`, check the environment, and confirm the three Python SDKs resolve together with the workspace pins (2026-10-09: they do, 184 packages, so all three are workspace members). Three spikes run in parallel: the Claude CLI traffic capture, the TypeScript full agent, and a kagent probe. Then a contract v5 draft covers three things: `/v1/messages` on the model proxy, a plain-A2A mode in the `remote` connector for third-party agents, and the freeze decision.
- **W1.** One task edits every shared registration file: the workspace, the import rules, the Dockerfiles, the CI matrix, and the image table. It also adds the skeletons, `acronym_expand`, and `bakeoff.yaml`.
- **W2.** The engines and the chassis changes: OpenAI Agents SDK, smolagents, Claude Agent SDK, `/v1/messages`, the benchmark kit, and kagent.
- **W3.** The lane bindings and suites. A new `poc06-kind.yml` workflow runs the kind checks on every push.
- **W4.** The scorecard, the Mac command, ADR-006, contract v5, and the READMEs.
- **W5.** The PR, green CI, and the hosted and SLM numbers from the Mac run.

Environment facts (2026-10-09):

- The Docker daemon starts in the cloud container, but Docker Hub answers 429.
- `curl` and `wget` are denied, so `kind` is not installed there.
- Node is 22 there, and 24 in CI.

So the image, Compose, and kind runs happen in CI and on the Mac.

## Risks

- **Time box.** The time box is 1 week per part. PoC-2 took 2 weeks for three engines.
- **kagent.** It is alpha (1.x). If the spike fails, record why and ask before picking another remote solution.
- **Kind memory.** Run one engine at a time on kind, because PoC-5 already uses about 3.3 GiB of the 7.75 GiB VM.
