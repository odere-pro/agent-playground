## Why

The epic requires an OpenAPI 3.1 spec for every API, with MCP tools generated from it, so REST and MCP never drift apart. The registry, the platform MCP server, and the documentation pack all read this spec or the `/manifest` built from it. Under [ADR-001](../adr/001-chassis-delivery-model.md), the chassis owns the public port, so the chassis builds the spec, not the workload. It is on the longest chain in the backlog, so it comes early in the chassis completion wave, right after service operations (050 CH-5).

## What

- An OpenAPI 3.1 spec generated by the chassis from its own endpoints plus the service's declared operations (050 CH-5). It covers every endpoint, the envelope, and the agent's own input and output JSON Schemas. The workload serves no public API, so it has nothing to add.
- The chassis serves the spec at `GET /openapi.json` ([contract v2](../../contracts/contract-v2.md)), and CI saves it as a build artifact. CI checks it with `openapi-spec-validator`.
- An MCP adapter in the chassis, built with FastMCP 4 ([ADR-003](../adr/003-chat-formats-onto-the-canonical-request.md), item 6). It generates MCP tools from the same spec and runs them through the same pipeline and engine connector. Built in PoC-3: the agent is one MCP tool at `/v1/mcp`, complete only, generated by `FastMCP.from_openapi` from the `/v1/run` operation. Its inner call to `/v1/run` forwards only `traceparent`, `tracestate`, and `Idempotency-Key`, and passes the same `spec.limits` checks as REST.
- The `spec.interfaces.mcp` config flag switches it on or off.
- MCP calls pass the same pipeline stages as REST: auth and scopes, limits, idempotency, and telemetry. The scopes are decided in [contract v6](../../contracts/contract-v6.md#d1-scopes-per-route): `agent:run` for `/v1/mcp`, `agent:read` for `/manifest` and `/openapi.json`.
- `GET /manifest`: the registry manifest, built from the agent config (name, version, class, kind, task, interfaces, scopes, events, governance block) plus the OpenAPI spec. It also reports:
  - the chassis version;
  - the lane (`spec.engine.connector`);
  - the trust value (`spec.trust`);
  - the workload and chassis image digests.
- `GET /manifest` v0 is built (`schemas/manifest.v0.json`, PoC-3).

## Reuse

- **Use:** FastMCP 4. `FastMCP.from_fastapi()` (or its OpenAPI provider) turns the OpenAPI spec into MCP tools, mounted in FastAPI with `http_app()`.
- **Build:** curated route maps (which operations become tools), and `/manifest` built from config plus the OpenAPI spec. The spec includes the service's declared operations (050 CH-5), and `/manifest` reports the chassis version, the lane, and the trust value.
- **Watch:** FastMCP 4 broke the 3.x APIs, so pin it. Do not use fastapi-mcp (no release since 2025-07).
- Details: [reuse analysis](../poc/010-reuse-analysis.md)

## Out of scope

- The AsyncAPI spec (052 H-21).

- The platform MCP server (094 P-1).
- The public A2A endpoint and its agent card (061 H-5).
- The LiteLLM MCP gateway's per-key grant in front of `/v1/mcp` (026 CH-4).

## Acceptance criteria

- [ ] The echo agent and the simplifier publish specs that pass OpenAPI 3.1 validation in CI: an `openapi-spec-validator` test, with the spec saved as a CI artifact. Today only a version-string check runs (`pocs/poc-03-one-interface-every-client/tests/test_openapi_props.py::test_the_spec_is_openapi_3_1_with_every_operation_named_and_labeled`).
- [x] An MCP client lists the simplifier's tools with `tools/list`, and a tool call gives the same output as `POST /v1/run`. · Delivered in PoC-3: `pocs/poc-03-one-interface-every-client/tests/test_exit_criteria.py::test_exit_4_an_mcp_client_lists_the_agents_tool_and_runs_it`; `packages/chassis/tests/test_mcp_interface.py::test_calling_the_tool_returns_the_native_response_envelope` (the echo workloads are the simplifier, `packages/workloads/README.md`).
- [x] A contract test fails if an MCP tool's input schema differs from the matching OpenAPI request schema. · Delivered in PoC-3: `packages/chassis/tests/test_mcp_interface.py::test_tool_input_schema_is_the_openapi_request_schema_of_run`; `pocs/poc-03-one-interface-every-client/tests/test_exit_criteria.py::test_exit_5_mcp_tools_and_rest_come_from_one_openapi_spec`.
- [ ] An MCP call without the `agent:run` scope gets 403 on `/v1/mcp`, shown by a test (`test_run_scope_is_needed_on_every_run_interface` covers the other three run routes only), and MCP calls appear in traces.
- [ ] `GET /manifest` returns the config fields, including the governance block, and changes when the config version changes.
- [x] `GET /manifest` reports the chassis version, the lane, and the trust value. · Delivered in PoC-3, PoC-5: `packages/chassis/tests/test_manifest.py::test_manifest_matches_the_config_and_the_openapi_spec`, `packages/chassis/tests/test_manifest.py::test_manifest_agent_trust_shows_untrusted_with_the_remote_lane`.
- [ ] `GET /manifest` reports the workload and chassis image digests, which match the running containers, and the agent's class, kind, and public address.
- [ ] The spec lists the service's declared operations, and a declared operation's MCP tool gives the same output as its REST route.
- [ ] A run with `status: error` answers as an MCP tool error (`isError: true`), not as a normal tool result ([the PoC-3 debt note](../../../pocs/poc-03-one-interface-every-client/notes/2026-10-01-debt.md)).
- [ ] No test reads FastMCP's private `tool._client`, so a FastMCP upgrade cannot break them unseen.
- [ ] Phase 0 done-when: the echo agent answers through the native, OpenAI, Anthropic, and MCP APIs and through events, streaming and complete where the API supports it, locally and in Kubernetes. It runs in the `sidecar` lane in Kubernetes and `inprocess` in tests. It appears in traces and passes contract tests for each API.
