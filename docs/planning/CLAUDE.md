# Planning workspace

Context for Claude Code when editing anything under `docs/planning/`. The root `CLAUDE.md` still applies.

## What this folder is

The planning workspace for the SLM agent platform: the epic, the backlog, the PoC track, and the ADRs. The code lives in `packages/` and `pocs/` at the repo root; this folder is its source of truth for design. Contents:

| Path | What it is | Edited how |
| ---- | ---------- | ---------- |
| `slm-agent-platform-epic-v3.md` | The epic: the source of truth for design | **Never edit.** `tools/check.py` fails if its checksum changes |
| `issues/` | Full platform backlog: one GitHub-issue file per epic story, plus `000-plan.md` | Bodies by hand; the rest generated (see below) |
| `poc/` | PoC track to the agent MVP, which runs first: `000-plan.md`, 9 iterations, `010-reuse-analysis.md` (mature tech picks) | By hand |
| `adr/` | Architecture decision records | By hand |
| `tools/` | Backlog generator and checks | Python |
| `diagrams/` | PNGs of the epic's figures, redrawn for ADR-001, plus the chassis lanes figure | Edit the Mermaid source in `diagrams/src/`, then re-render (see `diagrams/README.md`) |

## Commands

From the repo root: `make planning-sync` and `make planning-check`. Or from this folder, with Python 3 and PyYAML:

```bash
python3 tools/sync.py          # regenerate the generated parts of issues/ (see below)
python3 tools/check.py         # epic unchanged, numbering, dependency order, story coverage, sections, links and anchors
python3 tools/check.py 37 67   # body checks for issues 037–067 only; every other check still runs
```

Run `sync.py` and then `check.py` after any change to `issues/`, `poc/`, or `adr/`. `make check` at the repo root runs `check.py` too.

## How the backlog is built

- **Source of truth:** `tools/backlog.py` `ROWS` holds each issue's position (its index, which is the execution order), ID, title, wave, priority, size, dependencies, epic refs, and a position note. `tools/reuse_map.py` holds each issue's `## Reuse` bullets.
- **Generated by `sync.py`:** issue frontmatter, `## Reuse`, `## Dependencies`, `## References`, file names, `NNN ID` references in `issues/`, `poc/`, and `adr/`, and `issues/000-plan.md`. The plan comes from `tools/plan-template.md`, where `{{L:ID}}` becomes an issue link and `{{R:W2}}` a wave's index range.
- **Hand-written:** issue bodies (`## Why`, `## What`, `## Out of scope`, `## Acceptance criteria`), and everything in `poc/` and `adr/`.
- **So:** to reorder, reprioritize, resize, or change dependencies, edit `ROWS`, never the frontmatter. To change the backlog plan's prose, edit `plan-template.md`, never `issues/000-plan.md`.
- **To add an issue:** add a row to `ROWS`, run `sync.py` (it creates a skeleton with a `<!-- BODY: ... -->` marker), write the body in place of the marker, then run `check.py`.
- **Issue IDs** are epic story IDs (`H-1`, `G-2`, ...). Issues that are not epic stories use a prefix that `check.py` skips in the coverage check: `DEC-` (decisions), `L-` (later phases), and `CH-` (chassis work from ADR-001).
- **`build()` asserts every dependency has a lower index.** Order must respect dependencies.

## Conventions

- **File names** are `NNN-<ID>-<slug>.md`. The 3-digit prefix sets the order on disk and the execution order.
- **Issue references** are written as `NNN ID` (for example `015 H-4`), so `sync.py` can rewrite them when issues are renumbered.
- **Issue body order:** Why, What, Reuse (optional), Out of scope, Acceptance criteria (a `- [ ]` list), Dependencies, References.
- **Acceptance criteria** must not depend on a higher-numbered issue. If a later issue extends the scope, say so under Out of scope.
- **Labels:** `story` / `decision` / `later`; `priority:P0`–`P3`; `phase:*`; `area:*`; `size:S|M|L` (S ≤ 1 day, M 2–3 days, L 4–5 days); `layer:chassis`, `agent-profile`, or `platform`. The milestone is the wave (W0–W12).
- **Epic citations** are relative links with anchors that exist in the epic: `<a id>` anchors such as `#f1`, `#b2`, `#r13`, `#fig2`, `#app-h`, or heading slugs such as `#phase-0-agent-harness`.
- **Values the epic does not give** are marked `suggested:`.
- **Style:** plain words, short sentences, one idea per sentence, US spelling. Match the existing docs.

## Current design direction

This context spans many files.

- **The agent server is a service chassis.** It is the standard every microservice is built with, and the agent is its first profile. Its shape:
  - inbound adapters (native REST, OpenAI, Anthropic, MCP, A2A, CloudEvents) map to one canonical request;
  - a pipeline runs every standard functional requirement;
  - an engine connector (`inprocess`, `sidecar`, or `remote`) runs the workload;
  - outbound proxies handle model, tool, and event calls.

  See `poc/000-plan.md`.
- **Swappable and testable from day 0.** Every external dependency sits behind a port, with an in-memory fake and one contract suite shared by the fake and every real adapter. `spec.adapters` and the profiles `fake`, `local`, and `cloud` pick the adapters. `make test` must pass offline with no keys.
- **How the chassis runs next to a service** is decided in `adr/001-chassis-delivery-model.md` (accepted 2026-09-29, option I5):
  - The chassis always runs in front and owns the public port. The workload plugs in behind it through a lane, picked by `spec.engine.connector`.
  - `sidecar` is the default: a chassis container and a workload container in one pod, with A2A on localhost. `remote` is for untrusted workloads (`spec.trust`), third-party images, and managed runtimes. `inprocess` is for tests and local runs only.
  - A2A is the one contract to workloads. There is no SDK and no local API of our own. One chassis image, set once in a shared Helm library chart, rolled out in rings.
  - Hard requirement 1: only the chassis holds credentials to internal services. Hard requirement 2: every lane is tested on every commit.
  - The work is in issues `CH-1` to `CH-8`. Open follow-ups are in the "ADR-001 follow-ups" section of `issues/000-plan.md`.
- **Tech picks** and what to avoid are in `poc/010-reuse-analysis.md`, verified on 2026-09-28. Re-check versions before adopting.
- **Open product decisions** (broker, first cloud, the public A2A endpoint, reuse stack) are tracked in `issues/001-DEC-1-resolve-open-decisions.md`.
